# 后端后续需要修改的问题清单

日期：2026-07-13

检查对象：`github.com/ecustship/ecust`，提交 `0b447ac`

说明：本轮只修改前端，本文件记录联调检查发现的后端问题，没有改动后端仓库。

## 1. 必须处理的问题

### 1.1 读取接口缺少权限校验

当前 `/api/v1` 统一执行 JWT 认证，但大部分读取路由只验证“是否登录”，没有验证具体读取权限。例如：

- 机组和实时接口没有检查 `engine:read`。
- 趋势接口没有检查 `trend:read`。
- 告警查询接口没有检查 `alarm:read`。
- 数据质量接口没有检查 `quality:read`。

前端已按登录响应中的 `permissions` 隐藏菜单和按钮，但前端显隐不能代替后端鉴权。自定义角色如果没有某项读取权限，仍可能通过直接调用接口获取数据。

建议在 `internal/server/router.go` 为相应读取路由增加 `requirePermission`。页面聚合路由 `/pages/*` 和 `/vessels/*` 也需要保持同样规则。

### 1.2 生产环境不能在数据库异常时静默回退 Mock

后端 README 说明数据库查询失败时会回退内存 Mock。正式船端或岸端部署中，这会造成“数据库故障但页面仍显示正常参数”的风险。

建议增加生产配置，例如：

```env
ALLOW_MOCK_FALLBACK=false
```

生产模式数据库不可用时应返回明确的 5xx 或数据源错误；Mock 回退只允许开发和演示环境。前端已经会显示接口错误，并会展示后端返回的 `source`。

## 2. 趋势接口问题

### 2.1 页面聚合趋势接口忽略查询条件

`GET /api/v1/vessels/{vesselId}/trend` 当前只读取 `hours`，不处理 `start`、`end`、`metrics` 和 `points`。因此不能用它实现真正的日期和参数查询。

前端当前绕过该限制，改用：

```http
GET  /api/v1/trends/tags
POST /api/v1/trends/query
```

如果后端继续保留页面聚合趋势接口，应补齐参数语义，或者在接口文档中明确标记为兼容接口，避免新前端继续误用。

### 2.2 `interval` 尚未降采样

`POST /trends/query` 接受 `interval`，但当前仍返回范围内全部原始点。半年和一年数据量较大时，接口响应、网络传输和浏览器绘图都会变慢。

建议后端按 `1m/5m/1h/1d` 实现时间桶聚合，并根据范围设置合理的最大返回点数。响应应明确返回实际采用的 interval。

### 2.3 单次最多 90 天与页面半年/一年查询冲突

当前前端会把超过 90 天的时间范围拆成多个请求，并按 `tagCode + timestamp` 去重合并。这可以完成联调，但会增加请求数和数据库压力。

建议后端在实现降采样后允许更长时间范围，或者提供专门的长期趋势聚合接口。

## 3. 导航和系统状态数据仍包含固定值

`VesselRealtimePage` 中 GPS、航向、姿态、风速风向、吃水、温湿度当前为后端代码固定值；`SystemStatusPage` 中 CPU、内存、网络延迟、传感器状态也有固定初始值。

这些值虽然来自后端响应，但并非数据库或采集端真实数据。建议：

1. 为导航、气象和船舶姿态建立正式 tagCode 或独立数据模型。
2. 从采集入库数据生成 `/vessels/{vesselId}/realtime`。
3. 系统状态从采集节点心跳和服务监控数据生成。
4. 暂无数据时返回 `null`、`MISSING` 或明确的占位状态，不返回看似真实的固定数值。

当前权限字典也没有 `navigation:read`。如果导航数据需要独立授权，应增加权限点并在对应路由检查。

## 4. Modbus 配置管理接口尚未实现

前端工程配置页当前仍是本地 UI，没有以下后端闭环：

- 配置版本列表和详情。
- 草稿保存与服务端校验。
- 点位通信测试。
- 应用、回滚和下发结果。
- 操作审计和最后操作人。

后端应按“前端 -> 后端鉴权/审计/版本 -> 采集端配置服务”的边界设计，后端自身不要直接读取 RS485 串口。接口完成前，前端不会把本地按钮标记成已经正式生效。

## 5. 建议统一的接口问题

### 5.1 页面告警接口只有确认，没有恢复

页面接口使用：

```http
POST /vessels/{vesselId}/alarms/{alarmId}/acknowledge
```

恢复则只能调用标准接口：

```http
POST /alarms/{alarmId}/reset
```

建议统一页面和标准告警接口的命名与状态操作，或者在页面接口下补充 reset 路由。

### 5.2 CORS 应使用生产白名单

当前 CORS 中间件会把请求的 Origin 原样写入 `Access-Control-Allow-Origin`。同域 Nginx 部署不依赖 CORS；若后续允许跨域部署，建议使用配置化域名白名单，不要接受任意 Origin。

## 6. 后端修改后的验收项

1. 无 `engine:read` 的自定义角色请求机组接口返回 `40301`。
2. 无 `trend:read` 的角色请求趋势接口返回 `40301`。
3. 无 `alarm:read` 的角色请求告警接口返回 `40301`。
4. 生产模式 PostgreSQL 停止后，接口明确报错，不返回 `source=MOCK`。
5. 趋势 interval 能显著减少半年和一年范围的返回点数。
6. 导航和系统状态固定值被真实采集值或明确的缺失状态替代。
7. CORS 只允许配置的前端域名。
