# 通信与信号映射使用文档

## 1. 功能定位

`通信与信号映射` 页面用于工程师根据船端 MODBUS/RS485 协议表配置信号点位。

船端信号，包括报警信号，均通过数据通信传输到本系统。报警判断由船端控制器、PLC 或主发模块完成，本系统不根据温度、压力等模拟量自行判断报警。本页面只负责：

- 配置 MODBUS/RS485 通信参数。
- 配置普通信号点位映射。
- 配置船端报警 bit 映射。
- 查看通信状态和原始帧调试信息。

## 2. 进入页面

在顶部导航进入：

```text
配置参数 -> 通信映射
```

页面名称为：

```text
通信与信号映射
```

进入后可以看到顶部操作按钮、状态卡片和四个配置页签。

## 3. 顶部操作按钮

### 导入 Excel

用于导入类似 `Main Genset RS485 Communication protocolsV3` 的协议表。

后续实现导入功能时，系统会自动识别：

- 模拟量信号区
- 报警信号区
- MODBUS 地址
- 功能码
- 单位
- 量程
- 报警 bit

### 导出配置

用于导出当前系统内的信号配置，便于备份、交付或现场复用。

### 测试通信

用于测试当前 MODBUS/RS485 参数是否可以正常连接船端设备。

测试时重点查看：

- 是否在线
- 响应时间
- 是否超时
- 是否有 CRC 错误
- 是否能读取指定寄存器

### 保存并应用

保存当前配置，并将配置应用到系统信号读取逻辑。

现场调试时建议每完成一组地址配置后保存一次，避免配置丢失。

## 4. 顶部状态卡片

顶部状态卡用于快速查看当前配置概况。

### 协议

显示当前通信协议，例如：

```text
MODBUS RTU
```

### 串口

显示当前 RS485 端口，例如：

```text
RS485-1
```

### 通信参数

显示波特率和帧格式，例如：

```text
9600 / 8N2
```

其中 `8N2` 表示：

- 8 个数据位
- 无校验
- 2 个停止位

### 信号点

显示当前已配置的普通信号数量。

### 活动报警

显示当前处于触发状态的报警映射数量。

注意：这里显示的是船端报警 bit 的当前状态，不是 UI 本地判断出来的报警。

## 5. 通信参数页签

通信参数页签用于配置系统如何连接船端设备。

### 协议

可选：

- MODBUS RTU
- MODBUS TCP

RS485 通信一般使用 `MODBUS RTU`。

### 端口

选择实际连接船端设备的串口。

示例：

```text
RS485-1
RS485-2
/dev/ttyUSB0
```

### 波特率

根据协议表填写。

当前参考协议表默认：

```text
9600
```

### 数据位

当前参考协议表默认：

```text
8
```

### 校验位

当前参考协议表默认：

```text
None
```

即无校验。

### 停止位

当前参考协议表默认：

```text
2
```

### 默认功能码

当前参考协议表使用：

```text
03
```

表示读取 Holding Register。

### 字节序

用于配置 32 位整数、浮点数等跨寄存器数据的解析顺序。

常见选项：

```text
ABCD
BADC
CDAB
DCBA
```

如果现场读取值明显异常，例如温度或压力数值极大、极小或跳变，可以检查字节序。

### 地址基准

用于处理协议表地址与底层读寄存器地址之间的偏移问题。

可选：

```text
1-based
0-based
```

如果协议表地址为 `40262`，但实际读取需要减 1，则需要检查地址基准配置。

### 从站地址

填写船端 MODBUS 从站 ID。

### 轮询周期

配置系统读取数据的周期，单位为毫秒。

示例：

```text
1000
```

表示每 1 秒读取一次。

### 超时

配置单次读取等待响应的最长时间，单位为毫秒。

### 重试次数

配置读取失败后的重试次数。

## 6. 信号点表页签

信号点表用于配置普通模拟量和状态量。

参考协议表中的模拟量区：

```text
Displays analog quantities（Function code 03）
```

主要字段包括：

```text
NO.
Signal Content
485 Address Code
Range
Unit
Note
```

### 表格字段说明

#### 启用

控制该信号是否参与读取和显示。

#### NO.

协议表中的序号。

#### Signal Content

协议表中的英文信号名称。

例如：

```text
Engine Speed
Coolant Temperature
Oil Pressure
```

#### 中文名称

系统内用于中文显示的名称。

例如：

```text
发动机转速
冷却水温度
滑油压力
```

#### 变量 Key

系统内部使用的唯一变量标识。

例如：

```text
genset.engineSpeed
genset.coolantTemperature
genset.oilPressure
```

后续页面显示、趋势曲线、报警映射都通过变量 Key 找到对应数据。

#### 功能码

当前参考表中普通信号默认使用：

```text
03
```

#### 地址

对应协议表中的 `485 Address Code`。

例如：

```text
40262
40263
40267
```

#### Bit

普通模拟量一般为空。

如果地址是类似 `40001.8`，则表示：

```text
寄存器地址：40001
Bit 位：8
```

#### 数据类型

常见类型：

```text
UInt16
Int16
UInt32
Float32
Boolean
```

普通寄存器值通常使用 `UInt16`。位地址通常使用 `Boolean`。

#### 范围

对应协议表中的 `Range`。

例如：

```text
0-3000
0-150
0-1000
```

#### 单位

对应协议表中的 `Unit`。

例如：

```text
rpm
℃
kPa
V
```

如果协议表写 `0.1V`，表示原始值需要乘以 `0.1` 后显示为 `V`。

#### 当前值

显示当前通信读取后的工程值。

#### 质量

显示该信号当前通信质量。

常见状态：

```text
Good
Timeout
CRC Error
Disabled
Invalid
```

#### 页面

显示该信号绑定到哪些 UI 页面。

例如：

```text
Main Engine
Engine System
Trend
```

## 7. 报警映射页签

报警映射用于配置船端报警 bit 对应的显示名称和显示位置。

注意：

```text
本系统不进行报警判断。
```

船端控制器已经完成报警判断，并通过 MODBUS bit 输出报警状态。UI 只读取该 bit 并显示。

参考协议表中的报警区：

```text
ALARM（Function code 03）
```

### 报警映射字段说明

#### 启用

控制该报警 bit 是否参与显示。

#### NO.

协议表中的报警序号。

#### 报警名称

协议表中的英文报警名称。

例如：

```text
Common Alarm
Common Shutdown Alarm
Fuel leakage alarm
```

#### 中文名称

系统中文显示名称。

例如：

```text
综合报警
综合停机报警
燃油泄漏报警
```

#### 变量 Key

系统内部报警变量标识。

例如：

```text
genset.commonAlarm
genset.fuelLeakageAlarm
```

#### 地址

报警所在寄存器地址。

例如：

```text
40001
40034
40097
```

#### Bit

报警所在 bit 位。

例如 `40001.0` 表示：

```text
地址：40001
Bit：0
```

#### 触发状态

协议表中的 `Alarm state`。

通常为：

```text
1
```

表示该 bit 读取为 `1` 时，船端报警已触发。

#### 当前状态

显示当前报警 bit 的实时状态。

例如：

```text
Active
Normal
```

#### 声音

控制该报警是否触发声音提醒。

注意：专注模式开启后，报警声音会被静音。

#### 显示位置

配置报警显示到哪里。

常见位置：

```text
Global Banner
Alarm Page
```

## 8. 实时调试页签

实时调试用于现场排查通信问题。

### 通信状态

显示：

- 连接状态
- 响应时间
- 成功率
- CRC 错误数
- 超时次数
- 最后轮询时间

### 原始帧日志

显示 MODBUS TX/RX 原始报文。

示例：

```text
TX 01 03 9D 46 00 06 1A C4
RX 01 03 0C 03 51 00 53 00 5A 01 86 01 40 7B 29
```

如果数据显示不正确，工程师可以通过原始帧判断是通信问题、地址问题、字节序问题还是单位换算问题。

## 9. 典型配置流程

### 第一步：确认通信参数

根据协议表设置：

```text
MODBUS RTU
9600
8 data bits
No parity
2 stop bits
Function Code 03
```

### 第二步：测试通信

点击 `测试通信`。

确认：

- 能连接设备
- 无 CRC 错误
- 响应时间正常
- 可以读取寄存器

### 第三步：导入或录入信号点表

根据协议表录入普通信号。

示例：

```text
Engine Speed -> 40262 -> rpm
Coolant Temperature -> 40263 -> ℃
Oil Pressure -> 40267 -> kPa
```

### 第四步：配置报警映射

根据协议表录入报警 bit。

示例：

```text
Common Alarm -> 40001.0 -> bit = 1
Fuel leakage alarm -> 40034.11 -> bit = 1
```

### 第五步：检查当前值

在信号点表和报警映射中检查当前值是否正确。

### 第六步：保存并应用

确认无误后点击：

```text
保存并应用
```

## 10. 常见问题排查

### 所有数据都无响应

检查：

- 串口是否正确
- 波特率是否正确
- 从站地址是否正确
- 接线是否正确
- A/B 是否接反

### 个别地址无数据

检查：

- 地址是否录错
- 地址基准是否需要减 1
- 功能码是否正确
- 该点是否实际存在传感器

### 数值明显不对

检查：

- 单位换算是否正确
- 缩放系数是否正确
- 数据类型是否正确
- 字节序是否正确

### 报警没有显示

检查：

- 报警地址是否正确
- Bit 位是否正确
- 触发状态是否为 1
- 该报警是否启用
- 是否绑定到报警页或全局横幅

### 报警显示但现场没有报警

检查：

- 是否读错 bit
- 是否地址基准错误
- 是否协议表版本不一致
- 是否船端仍保持报警状态未复位

## 11. 工程边界说明

本页面只配置通信映射，不承担船端保护逻辑。

系统不做：

- 高温报警判断
- 低压报警判断
- 停机保护判断
- 报警延时判断
- 报警恢复判断

系统只做：

- 读取船端信号
- 解析寄存器和 bit
- 显示当前值
- 显示船端报警状态
- 播放或静音报警声音
- 记录报警历史
